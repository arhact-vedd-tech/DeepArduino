## Глава 7: Serial

### Цель

Научиться использовать Serial для отладки и двусторонней связи. Без этого любая следующая глава превращается в гадание: «работает или мне кажется».

### Что такое Serial на Uno

Uno имеет один аппаратный UART на пинах **D0 (RX)** и **D1 (TX)**. Эти же пины подключены к USB-мосту ATmega16U2, поэтому когда плата подключена к компьютеру, Serial — это канал связи с монитором порта в VSCodium.

**Следствие**: если ты используешь `Serial`, пины D0/D1 заняты. Не подключай к ним внешние устройства, если нужен монитор порта. Для дополнительных UART — `SoftwareSerial` на любых других пинах (разберём позже, если понадобится).

### Инициализация

```cpp
void setup() {
  Serial.begin(9600);
}
```

`9600` — скорость в бодах. Должна **совпадать** с настройкой монитора порта. Если не совпадает — увидишь мусор вместо текста .

Стандартные скорости: 9600, 19200, 38400, 57600, 115200. Для отладки достаточно 9600. Для быстрой передачи больших объёмов — 115200.

### Вывод: `print` и `println`

```cpp
Serial.print("raw=");
Serial.print(analogRead(A0));
Serial.println(" done");
```

| Функция | Что делает |
|---|---|
| `Serial.print(x)` | Выводит `x` **без** перевода строки |
| `Serial.println(x)` | Выводит `x` **с** переводом строки (`\r\n`) |

`println` без аргумента выводит пустую строку (только перевод).

**Формат чисел**:

```cpp
Serial.println(3.14159, 2);  // 3.14 — два знака после запятой
Serial.println(255, HEX);    // FF
Serial.println(255, BIN);    // 11111111
```

### Отладка: главный паттерн

```cpp
const byte BUTTON_PIN = 2;

void setup() {
  Serial.begin(9600);
  pinMode(BUTTON_PIN, INPUT_PULLUP);
  Serial.println(F("=== Start ==="));
}

void loop() {
  static bool lastState = HIGH;
  bool currentState = digitalRead(BUTTON_PIN);

  if (currentState != lastState) {
    Serial.print(F("Button: "));
    Serial.println(currentState == LOW ? F("PRESSED") : F("RELEASED"));
    lastState = currentState;
  }
}
```

`F("...")` хранит строку во Flash, а не в SRAM. На Uno с 2 КБ SRAM это не микрооптимизация, а необходимость, если строк много.

**Правило**: любая ветка логики, которая «не срабатывает», должна иметь `Serial.println` на входе. Если строка не появилась — проблема до этой ветки. Если появилась, но поведение не то — проблема внутри.

### Приём данных: `available` и `read`

Serial — не только вывод. Можно отправлять команды из монитора порта на плату.

```cpp
void loop() {
  if (Serial.available() > 0) {
    char c = Serial.read();
    Serial.print(F("Got: "));
    Serial.println(c);

    if (c == '1') digitalWrite(LED_BUILTIN, HIGH);
    if (c == '0') digitalWrite(LED_BUILTIN, LOW);
  }
}
```

| Функция | Назначение |
|---|---|
| `Serial.available()` | Сколько байт пришло и ждёт чтения |
| `Serial.read()` | Прочитать **один** байт (и удалить из буфера) |
| `Serial.readString()` | Прочитать всё до таймаута в `String` — **дорого по SRAM, избегай** |

`read()` возвращает `-1`, если буфер пуст. Поэтому всегда проверяй `available() > 0` перед чтением.

### Монитор порта в VS Arduino

Расширение HiTECH предоставляет монитор порта как панель внизу или вкладку редактора .

**Открыть**: `Ctrl+Shift+P` → **VS Arduino: Open Serial Monitor** (или аналогичная команда в палитре) .

**Настройки**:
- **Baud rate** — должен совпадать с `Serial.begin()`. В настройках расширения есть `vs-arduino.baudRate`, по умолчанию `"115200"` . Если у тебя в скетче `9600`, а монитор на 115200 — увидишь мусор.
- **Line ending** — что добавляется к отправляемым данным. Для `Serial.read()` одного символа — «No line ending». Для команд вроде `LED ON` — «Newline» или «Both NL & CR», чтобы `readStringUntil('\n')` мог найти конец .

**Двусторонняя связь**: в мониторе есть поле ввода. Набираешь символ, жмёшь Enter — он уходит на плату, `Serial.read()` его получает .

### Что может пойти не так

- **Мусор в мониторе** — несовпадение baud rate. Проверь `Serial.begin()` и настройку монитора .
- **Пусто в мониторе** — либо монитор не открыт, либо `Serial.begin()` не вызван, либо порт занят другой программой (Arduino IDE, другое окно VSCodium). Закрой всё, что держит порт.
- **`Serial.read()` возвращает `-1`** — нет данных. Проверяй `available()`.
- **Отправляешь команду, плата не реагирует** — либо line ending не тот, либо скетч ждёт символ, а ты отправил строку, либо `Serial.read()` вызывается без проверки `available()` и читает пустоту.
- **Пины D0/D1 подключены к внешнему устройству** — загрузка скетча может падать, Serial может не работать. Освободи их.

### Задание

1. Скетч: каждые 500 мс выводит `millis()` и значение `analogRead(A0)`. Открой монитор, убедись, что видишь данные. Покрути потенциометр — значения меняются.
2. Добавь обработку: если в монитор отправить `'1'` — светодиод на пине 8 горит, `'0'` — гаснет. Отправляй символы без line ending.
3. Усложни: команда `LED 128` (строка) устанавливает яркость ШИМ на пине 9. Подсказка: `Serial.readStringUntil(' ')` для числа, но это `String` — для Uno терпимо в учебном скетче, в проекте лучше `parseInt()`. Сделай и сравни расход SRAM.
