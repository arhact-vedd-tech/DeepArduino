## Глава 14: Flappy Bird / Змейка на OLED

### Цель

Собрать одну прошивку с двумя играми и меню выбора. Освоить три техники, без которых игры на Uno не работают: **фиксированный игровой цикл без `delay()`**, **спрайты в `PROGMEM`** и **целочисленная физика без `float`**.

### Реальность Uno: 2 КБ SRAM

Обе игры в одной прошивке — это тесно. Решение — не хранить в SRAM ничего, что можно хранить во Flash. Спрайты, строки меню, таблицы — всё в `PROGMEM` . Переменные игры — только `int`, `byte`, `bool`. Никаких `String`, никаких `float`.

### Железо

| Компонент | Пин | Примечание |
|---|---|---|
| OLED 128×64 SSD1306 I2C | A4 (SDA), A5 (SCL) | Адрес `0x3C` или `0x3D` |
| Кнопка «действие» | D2 | `INPUT_PULLUP`, нажатие = `LOW` |
| Кнопка «меню/назад» | D3 | `INPUT_PULLUP`, опционально |

Для Змейки одной кнопки мало. Варианты: джойстик на A0/A1 (аналоговый), или четыре кнопки на D4–D7. В коде ниже — кнопка D2 для Flappy и джойстик для Змейки (как в референсе Elecrow ).

### Библиотеки

`Adafruit SSD1306` + `Adafruit GFX Library`. Установка через Library Manager в VS Arduino (глава 8).

### Архитектура: игровой цикл

```cpp
const unsigned long FRAME_MS = 33;  // ~30 FPS
unsigned long lastFrame = 0;

void loop() {
  unsigned long now = millis();
  if (now - lastFrame < FRAME_MS) return;
  lastFrame = now;

  readInput();
  updateGame();
  render();
}
```

`return` вместо `delay(33)` — `loop()` крутится свободно, кнопки читаются в каждом проходе, но игровая логика обновляется ровно 30 раз в секунду. Это стандартный паттерн для Arduino-игр .

### Flappy Bird: физика без float

Гравитация и скорость в пикселях — дробные. `float` на AVR дорог и медленен. Решение из рабочей реализации: **все координаты и скорости умножить на 10** и хранить как `int` .

```cpp
const int SCALE = 10;
const int GRAVITY = 5;        // 0.5 px/frame
const int JUMP_VELOCITY = -25; // -2.5 px/frame

int birdY = 32 * SCALE;  // 32.0 px
int velocity = 0;        // тоже scaled

void updateBird() {
  velocity += GRAVITY;
  birdY += velocity;
  // отрисовка: display.drawPixel(x, birdY / SCALE, WHITE)
}
```

При нажатии кнопки: `velocity = JUMP_VELOCITY`. Трубы двигаются влево с фиксированной скоростью, генерируются с случайным зазором. Столкновение — сравнение `birdY` с границами зазора.

**Спрайт птицы** — 10×8 пикселей, массив `uint8_t` в `PROGMEM`, отрисовка через `display.drawBitmap(x, y, bitmap, w, h, WHITE)` .

### Змейка: сетка и очередь

Поле 128×64. Клетка 4×4 пикселя → сетка 32×16. Змейка — массив координат головы и хвоста.

```cpp
const byte CELL = 4;
const byte GRID_W = 32;
const byte GRID_H = 16;

struct Point { byte x, y; };
Point snake[64];  // максимум 64 сегмента
byte snakeLen = 3;
byte dir = 1;     // 0=up, 1=right, 2=down, 3=left
```

Каждый кадр: голова сдвигается на одну клетку в текущем направлении, остальные сегменты сдвигаются по цепочке. Еда — случайная свободная клетка. Столкновение со стеной или с собой — game over.

Джойстик читается через `analogRead(A0)` и `analogRead(A1)`, направление определяется по порогам (например, `< 300` или `> 700`). Антидребезг не нужен — джойстик аналоговый, но нужна мёртвая зона.

### Меню выбора

```cpp
enum Game { MENU, FLAPPY, SNAKE };
Game current = MENU;

void loop() {
  switch (current) {
    case MENU:   drawMenu();   if (buttonPressed()) current = FLAPPY; break;
    case FLAPPY: runFlappy();  if (exitPressed())   current = MENU;   break;
    case SNAKE:  runSnake();   if (exitPressed())   current = MENU;   break;
  }
}
```

Каждая игра — функция, которая вызывается из `loop()` и сама решает, когда вернуться. Меню рисует два пункта, выбор — кнопкой D2, выход — D3.

### Что может пойти не так

- **`SSD1306 allocation failed`** — адрес не `0x3C`/`0x3D` или дисплей не отвечает. Проверь I2C-сканером (глава 10).
- **Игра тормозит** — `FRAME_MS` слишком мал, или в `render()` много вызовов `display.display()`. `display.display()` вызывай **один раз за кадр**, после всей отрисовки.
- **Птица проваливается сквозь трубы** — `velocity` scaled, но сравнение с границей не scaled. Приведи к одному масштабу.
- **Змейка «застревает»** — смена направления на противоположное (влево при движении вправо). Запрещай разворот на 180°.
- **SRAM закончилась** — компилятор покажет в отчёте. Убери глобальные массивы, оставь только необходимое. Спрайты — в `PROGMEM` .

### Задание

1. Собери Flappy Bird. Добейся, чтобы птица летала, трубы двигались, столкновение работало.
2. Добавь счёт: сколько труб пройдено. Выводи в верхнем углу OLED.
3. Собери Змейку. Используй джойстик или четыре кнопки. Проверь, что еда не появляется на змейке.
4. Объедини в одну прошивку с меню. Проверь расход SRAM в отчёте компилятора — он должен быть **меньше 1500 байт**, иначе игры будут нестабильны.
