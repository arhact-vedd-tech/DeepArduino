## Глава 3: Язык Arduino (C++ под капотом)

### Цель

Разобраться с синтаксисом, который реально используется в скетчах. Не учебник C++, а рабочая выжимка: переменные, условия, циклы, функции. Всё, что дальше встретится в коде — будет понятно.

### Главное, что нужно принять сразу

Arduino — это **не отдельный язык**. Это C++ с готовыми библиотеками и двумя обязательными функциями. Всё, что знаешь про C++ — работает. Всё, чего не знаешь — можно не знать, пока не понадобится.

### Структура скетча

```cpp
void setup() {
  // выполняется один раз при старте или после сброса
}

void loop() {
  // выполняется бесконечно, пока есть питание
}
```

`setup()` и `loop()` — обязательны. Всё остальное — твой код: переменные, функции, `#include`.

### Переменные и типы

Тип определяет, сколько памяти занимает переменная и какие значения может хранить. На Uno это критично (2 КБ SRAM).

| Тип | Размер | Диапазон | Когда использовать |
|---|---|---|---|
| `byte` / `uint8_t` | 1 байт | 0–255 | Пины, счётчики, флаги |
| `int` | 2 байта | −32768…32767 | Общие целые числа |
| `unsigned int` | 2 байта | 0–65535 | Когда отрицательные не нужны |
| `long` | 4 байта | ±2,1 млрд | `millis()`, большие счётчики |
| `float` | 4 байта | ~7 значащих цифр | Измерения, но **дорого** по тактам |
| `bool` | 1 байт | `true`/`false` | Флаги состояний |
| `char` | 1 байт | −128…127 или символ | Символы, строки |

**Правило**: по умолчанию — `int`. Если значение не превысит 255 и отрицательных не будет — `byte`. Если работаешь со временем (`millis()`) — **всегда `unsigned long`** .

```cpp
int ledPin = 13;
byte brightness = 128;
unsigned long lastTime = 0;
bool isOn = false;
```

**Область видимости**: переменная, объявленная внутри `loop()` или `setup()`, существует только там. Объявленная до функций (глобально) — видна везде. Глобальные переменные занимают SRAM постоянно — не плоди их без нужды.

### Константы

```cpp
const int LED_PIN = 13;
const float THRESHOLD = 2.5;
```

`const` — компилятор не даст изменить значение. Если константа — используй `const`. Если константа целочисленная и известна на этапе компиляции — `#define` тоже работает, но `const` безопаснее (типизирован).

### Условия

```cpp
if (temperature > 25) {
  digitalWrite(FAN_PIN, HIGH);
} else if (temperature > 20) {
  // ничего не делаем
} else {
  digitalWrite(FAN_PIN, LOW);
}
```

Операторы сравнения: `==` (равно), `!=` (не равно), `>`, `<`, `>=`, `<=`.
Логические: `&&` (И), `||` (ИЛИ), `!` (НЕ).

**Классическая ошибка**: `if (x = 5)` вместо `if (x == 5)`. Первое — присваивание (всегда истина), второе — сравнение. Компилятор предупредит, но не остановит.

### Циклы

```cpp
// for — когда известно число итераций
for (int i = 0; i < 10; i++) {
  digitalWrite(LED_PIN, HIGH);
  delay(100);
  digitalWrite(LED_PIN, LOW);
  delay(100);
}

// while — когда условие важнее счётчика
while (digitalRead(BUTTON_PIN) == LOW) {
  // ждём отпускания кнопки
}

// do-while — тело выполнится хотя бы раз
do {
  // ...
} while (condition);
```

**Осторожно с `while` и `delay`**: они блокируют `loop()`. Всё, что должно происходить параллельно (обработка кнопок, обновление дисплея), в это время стоит. В главе 11 разберём, как от этого избавиться через `millis()`.

### Функции

```cpp
void blink(int times, int durationMs) {
  for (int i = 0; i < times; i++) {
    digitalWrite(LED_PIN, HIGH);
    delay(durationMs);
    digitalWrite(LED_PIN, LOW);
    delay(durationMs);
  }
}

void setup() {
  pinMode(LED_PIN, OUTPUT);
}

void loop() {
  blink(3, 500);
  delay(2000);
}
```

- `void` — функция ничего не возвращает.
- `int` перед именем — возвращает целое: `return value;`.
- Параметры — то, что передаётся в функцию. Если параметр не должен меняться внутри — `const`.

**Зачем функции**: код в `loop()` длиннее 30–40 строк — сигнал, что пора разбивать на функции. Это не стиль, это управляемость: одну функцию проще отладить, чем поток сознания в `loop()`.

### Массивы

```cpp
int pins[] = {3, 5, 6, 9};
for (byte i = 0; i < 4; i++) {
  pinMode(pins[i], OUTPUT);
}
```

Индексация с нуля. Выход за границы массива **не проверяется** — программа просто читает/пишет чужую память. Это источник самых неприятных багов на Arduino.

### Строки

Два подхода:

```cpp
// C-строка (char array) — экономно по SRAM
char msg[] = "Hello";

// String — удобно, но дорого и фрагментирует SRAM
String s = "Hello";
s += ", world";
```

**Правило для Uno**: `String` использовать только если очень нужно и редко. Для вывода в Serial — `Serial.print("text")`, это не создаёт `String`. Для хранения текста — `char[]` или `F("text")` (хранит строку во Flash, а не в SRAM).

```cpp
Serial.println(F("This string lives in Flash, not SRAM"));
```

### Что может пойти не так

- **`int` переполняется**: `int x = 32767; x++;` → −32768. Для счётчиков времени — `unsigned long`.
- **`millis()` обернётся через ~49 дней** — если сравниваешь `if (millis() > lastTime + 1000)`, через 49 дней сломается. Правильно: `if (millis() - lastTime > 1000)` — разность `unsigned long` корректна при переполнении.
- **Деление целых**: `5 / 2 == 2`, не 2.5. Нужен `float` — `5.0 / 2`.
- **`String` в цикле** — фрагментация SRAM, зависание через часы работы. Не делать.
